# 합성 텍스트 상태 재생

## 구성

`playback.py`에 변경할 수 없는 예시 3단계를 미리 저장했다. 각 단계는 A/B/C의 텍스트 기록이며 ID·예시 시각이 서로 다르다. 이동 경로·위치·속도·실제 기체 정보는 사용하지 않는다. 원래 고정 A/B/C 기록도 유지한다.

`GET /api/playback?frame=0`, `1`, `2`로 단계를 조회한다. 서버 재생 상태를 변경하는 명령이 아니라 고정 예시 조회다. `POST /api/summary`의 `{"playback_frame":1}`은 2단계의 고정 스냅샷을 하나의 모델 요청으로 설명한다. 생략하거나 null이면 기존 초기 기록을 설명한다. 외부 기록 데이터나 사용자 지시는 이 요청에서 받지 않는다.

화면의 재생 버튼은 첫 단계부터 시작한다. 다음 단계는 5초 뒤에 조회하고 자동 요약을 켰으면 요약 완료 후 다음 5초를 예약한다. 모델 지연을 포함하므로 정확히 5초마다 바뀌는 실시간 스트림은 아니다. 3단계 끝에 멈춘다. 일시정지는 다음 단계 예약을 취소하며 이미 실행 중인 모델 요청은 완료된다. 다음 단계 버튼으로 수동 진행할 수도 있다. 초기 기록으로 돌아가기는 원래 고정 기록을 다시 불러온다.

자동 요약을 끄면 기록만 바뀐다. 전체 기록 요약 요청 버튼으로 수동 요약할 수 있다. LLM 표시를 끄면 자동 요약도 요청하지 않는다. 읽음은 기록 ID별로 구분되어 이전 단계의 읽음이 새 단계로 넘어가지 않는다. 개별 질문과 전체 요약은 공통 잠금을 사용한다. 요약 생성 중 재생 단계 변경은 기다린다. 모델 실패를 실제 장치 상태 변화로 해석하지 않는다.

이전 요약이 남아 있을 때는 이전 시점의 설명임을 표시한다. 근거 버튼은 현재 단계에 없는 기록을 다른 기록으로 잘못 이동시키지 않는다. 서버에서는 생성 중 다른 단계 조회가 발생해도 요청 시의 고정 입력과 비교하여 답변을 검사한다. 원본 인용 검사는 의미 정확성을 보장하지 않는다.

## 사용자 확인 순서

1. 기존 README의 데모 시작 절차로 화면을 연다. 기존 다른 작업이 기본 포트를 사용 중이면 임의 종료하지 않는다.
2. 재생을 누르고 예시 기록 ID·내용·시각이 단계별로 바뀌는지 본다.
3. 자동 요약의 대상 단계·근거 ID·시각이 표시된 예시와 맞는지 본다.
4. 일시정지, 다음 단계, 자동 요약 끄기, 초기 기록으로 돌아가기를 확인한다.
5. 모델을 사용할 수 없어도 원본 기록은 남으며 실패 안내가 보이는지 확인한다.

## 검증과 한계

기존 검사를 포함한 Python unittest 26개 통과. 새 4개 검사는 단계별 ID·내용 변경과 원본 보존, 읽음 분리, 요청 단계별 요약, 잘못된 단계 거부, 이전 단계 모델 응답 거부, 생성 도중 다른 단계 조회의 스냅샷 보존을 확인했다. UI JavaScript 구문 검사 통과. 실제 브라우저 타이머·클릭·레이아웃은 기존 접근 제한으로 미검증이며 우회하지 않았다.

실제 Qwen 모델의 2단계 응답과 종료 증거는 `playback-live-results.json`에 저장했다. HTTP 200, 약 6.55초, 세 기록의 ID·시각·인용 검사 통과와 초기 원본 보존을 확인했다. 기존 11434 모델 서버는 보존하고 프로젝트 모델만 임시 11435에서 시험했다. 자신이 시작한 모델은 종료 코드 0과 포트 닫힘을 확인했다. 기체·Gazebo 실행, 새 설치·다운로드, 제어 기능은 추가하지 않았다.
