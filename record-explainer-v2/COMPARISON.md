# 동일 합성 기록의 LLM 보조 유무 비교

목적은 이 데모에서 확인 시간·누락·정확성이 어떻게 달라지는지 관찰하는 것이다. 실제 사용자 측정은 수행하지 않았으며 인지부하 감소·인력 절감·임무 성공률 향상을 주장할 수 없다.

## 조건

- A: LLM 설명 영역 표시를 끄고 원본만 확인한다.
- B: 같은 원본을 보며 LLM 설명을 사용할 수 있다.
- 같은 컴퓨터·같은 모델·같은 기록·같은 질문을 사용한다. 실행 버전과 모델 최초 로딩 여부를 기록한다.
- 참가자는 임의 코드로 기록한다. 이름·개인정보는 수집하지 않는다.
- 각 조건 전에 서버를 재시작해 읽음을 초기화하고 페이지를 새로 열어 질문 이력을 초기화한다.
- 참가자별 A→B/B→A 순서를 번갈아 배정한다. 동일 기록의 반복으로 학습 효과가 생기므로 이를 결과 한계에 포함한다.

## 확인 과제와 정답 기준

1. A의 원본 ID·시각·상태·해결 여부를 적는다. 기준: TEST-A-001, 14:00 KST, 연결 확인 실패, 해결 여부 확인 불가.
2. B가 정상인지 판단할 수 있는지와 근거를 적는다. 기준: TEST-B-001, 14:01 KST, 연결 결과 없음으로 판단 불가.
3. C에 읽음 표시를 하고 해결 여부가 바뀌었는지 확인한다. 기준: TEST-C-001, 14:02 KST, 읽음만 변경되고 해결 여부는 제공되지 않음.

시각의 날짜는 모두 2026-10-09이며 고정 합성 시각이다. 참가자에게 정답을 미리 보여주지 않는다.

## 기록 방법

시작 신호부터 세 답을 제출할 때까지 걸린 시간을 측정한다. 모델 대기 시간도 포함하되 모델 생성 시간은 별도 기록한다. 답변에서 누락된 필수 항목 수와 틀린 항목 수를 구분한다. 확인 부담은 조건 종료 직후 참가자 자신의 1~7점으로 받으며 표준화된 인지부하 측정이나 객관적 성공률로 해석하지 않는다.

`measurement-template.csv`는 빈 기록 양식이다. 측정하지 않은 값을 채우지 않는다. 소수 참가자·합성 기록 3건의 결과를 실제 운용으로 일반화하지 않는다. 원본 인용·ID가 맞아도 모델 설명의 의미 오류는 사람이 별도로 확인한다.

## 화면에서 기록하고 내보내기

1. 원본 목록이 로드된 뒤 조건 A는 설명 영역 표시를 끄고, 조건 B는 켠다.
2. 시작 신호에 맞춰 측정 시작을 누른다. 측정 중 조건 전환은 잠긴다.
3. 위 세 과제를 수행하고 답을 제출한 뒤 측정 종료를 누른다. 모델 대기 시간은 전체 경과 시간에 포함된다. 생성 중에는 종료 버튼이 잠겨 완료/실패 후 종료한다.
4. 완료 측정 CSV 내보내기를 눌러 저장한다. 다음 페이지 초기화 전에 저장한다.

CSV의 `elapsed_ms`는 시작과 종료 클릭 사이의 단조 시계 경과 시간이다. `ui_click_events`는 측정 도중 버튼·입력·선택·텍스트 영역에 발생한 사용자 click 이벤트 수다. 측정 버튼과 프로그램이 만든 다운로드 클릭은 제외한다. 키보드로 버튼을 실행할 때도 click 이벤트가 발생하면 포함하지만 Tab 이동·타이핑은 세지 않는다. 물리적인 마우스 클릭 수나 모든 사용자 동작 수로 해석하지 않는다. `question_requests`는 재시도를 포함한 설명 요청 시도 수이며 성공 수와 다르다.

시작·종료 시각, 질문 내용, 사용자 이름은 CSV에 넣지 않는다. 완료된 조건·시간·횟수만 포함한다. 모델 생성 시간, 정답의 누락·오류, 부담 평점은 기존 빈 양식에 별도 기록한다. 내보내기 코드와 집계 로직은 검사했지만 실제 브라우저 다운로드는 아직 미검증이며 측정 결과 데이터도 없다.
