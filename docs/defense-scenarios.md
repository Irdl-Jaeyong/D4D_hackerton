# 외부 접근 상황과 운용자 대형 선택

상황 발생은 외부 모의 선박만 생성하며 함대 대형을 바꾸지 않는다. 운용자가 USV/UAV 대형 버튼을 직접 선택하면 함선 상대 대형이 점진적으로 전환된다. 후방 상황에서 UAV V자는 후방을 향하고 전방 상황에서 UAV 삼각형은 전방 관측 위치로 전개한다.

| 상황 | 외부 접촉 | 참고 대형 (USV / UAV) |
| --- | --- | --- |
| 주변 미식별 접촉 | 측면 1척 | 원형 / 다중 링 |
| 전방 고속 접근 | 전방 1척 | 부채꼴 / 삼각형 |
| 양측 동시 접근 | 좌·우현 2척 | 2열 / 박스 |
| 후방 추적 접근 | 후방 1척 | V자 / V자 |

대응안 실행은 선택 사항이다. 실행하면 UAV는 접촉을 지속 추적하고 USV는 접촉과 함선 사이 경계선을 유지한다. 실행 중 대형 버튼을 누르면 수동 운용으로 인계하고 출동 기체는 선택된 대형에 복귀한다. 외부 접촉은 계속 표시한다. 상황 종료로 접촉을 제거할 수 있다.

시작할 때 `startup_mode: normal` 설정으로 이전 상황·모의 고장·에너지 추정 이력을 초기화하고 원형 USV·반구 UAV 정상 호위로 시작한다. 10초 동안 정상 상태를 보여준 뒤 첫 상황이 발생한다. 이후에는 120초(2분) 간격으로 추가한다. `startup_mode: resume`으로 바꾸면 이전 관제 상태를 복원한다.

자동 상황 생성은 120초(2분) 간격, 승인 대기 최대 4건, 표시 상위 3건이다. 구조·장애물은 이전 API 호환용으로 유지하지만 자동 생성 후보에서 제외했다. 고장은 자동 생성 후보에서 제외하며 기존 고장 기체 표현은 유지한다.

설정은 config/defense_scenarios.json (방위·접근 속도·거리·참고 대형), config/approval_risk.json (규칙 점수), config/auto_scenarios.json (주기·최대 건수)에서 수정한다. 위험도는 규칙 기반이며 실제 적대 의도를 확정하지 않는다.

시각 개선: 소형정 메시의 면 방향·법선·MTL 재질을 명시하고, 선체·고무·유리의 거칠기를 구분했다. 좌석·난간을 추가하고 항적 길이를 접촉 속도에 맞췄다. 바다 색과 일광은 함께 조정하고, 전체 카메라는 모든 접근 방향을 포함하면서 함선을 더 크게 보여준다. 이동 제어와 시나리오 항로는 그대로다.

외부 소형정은 원본 12m 곡면 메시, 갑판·고무 칼라·유리·선외기·항해등·항적으로 표현한다. 3D 카메라와 지도 범위는 외부 접촉을 포함하며 접촉 식별·거리 표시는 화면 오버레이다.

## 시뮬레이션 범위

외부 접근 선박의 항로와 파도에 따른 자세, UAV 이동은 위치 갱신 기반 시연이다. USV는 기존 부력·추진력 기반 제어를 유지한다. 접촉 항로는 안전 거리를 유지하는 비무장 접근 시나리오이며 실제 센서 탐지·분류, 충돌 동역학, 무장 교전은 구현하지 않는다. 따라서 이 결과를 실제 방어 성능 검증으로 해석하지 않는다.

## 추가 방어 관측 상황

- `air_intrusion`: 95m 공역의 미식별 고정익 드론. UAV는 고도 분리 관측, USV는 수상 경계 유지.
- `combined_intrusion`: 서로 다른 방향의 공중 드론과 수상 소형정. 접촉별로 관측·경계 기체를 분리 배정.
- `suspicious_float`: 부유 상자와 드럼. UAV 관측 및 USV 안전 거리 확인. 내용물과 적대성은 미확인.
- `communication_interference`: 모의 전파 교란 구역(점선 구역 표시). 가용 UAV·USV 각 1대에 기존 통신 고장 동작을 적용. 자동 추천 갱신은 고장을 해제하지 않으며 상황 종료 시 이 상황이 적용한 통신 고장을 해제.
- `underwater_contact`: 수면 아래 모의 접촉과 수면상의 추정 구역. 실제 소나 측정이나 수중 탐지 성공을 주장하지 않으며, USV 수중 센서 탑재는 시나리오 가정이다.

외부 접촉 식별 문구는 선박·드론·부유물·교란 구역·수중 추정으로 나눈다. 항로와 영역은 시나리오 데이터이며 실제 기체 텔레메트리와 구분한다. 모든 상황은 운용자 대형 선택을 유지하며 자동 생성 후보는 기존 4종을 포함한 9종이다.

추가 시각 개선: 아군 UAV에 원본 둥근 복합재 셸·관측 카메라 짐벌·반투명 로터 회전 표현을 적용했다. 해면 노멀에 작은 잔물결 층을 더했고 웹 영상 JPEG 품질을 85에서 92로 높였다. 대형·비행 경로·센서 주기는 유지했다.

## 선택 기체 1인칭

기체를 선택하고 `선택 기체 · 1인칭` 버튼을 누르면 기체 전방의 가상 탑재 카메라로 전환한다. UAV는 기수, USV는 전방 센서 위치, 함선은 전방 상부 위치에서 바라본다. 위치와 자세 회전을 모두 반영하며 USV는 실제 오도메트리 위치·방향·높이·흔들림을 사용한다. 1인칭에서 다른 기체를 목록이나 지도에서 선택하면 그 기체로 전환하고 `전체 보기`로 복귀한다. 탑재 위치와 하향 각도는 config/fleet.json의 first_person_camera에서 수정한다. 이 카메라는 Gazebo 가상 센서이며 실제 기체 카메라 하드웨어는 아니다.

기체 전환마다 카메라 선택 revision을 갱신한다. Gazebo pose 적용 성공 이후 새로 구독한 시뮬레이션 시각을 확인하고, 그 시각 이후 촬영된 선택 기체 영상만 수신한다. 이전 기체 영상이 새 기체 영상으로 표시되지 않도록 백엔드에서도 선택·촬영 시각을 검증한다.

## 시나리오별 대응안 2개

9개 방어 상황의 대응안은 `config/defense_responses.json`에 2개씩 총 18개로 정의한다. 관측·경계를 집중하는 방법과 호위를 유지하거나 함선을 가까이 보호하는 방법 등 목적이 다른 두 안을 남겼다. 기존 대응 ID는 유지하며 표시 번호는 각 상황의 1번·2번이다. 배정 상세 선택지는 실제 대응 목록으로 생성한다. 일반·고장 상황도 2개를 생성한다. AI 설명은 제공된 두 안만 비교하도록 지시한다.

| 상황 | 1번 | 2번 |
|---|---|---|
| 주변 미식별 선박 접촉 | 식별 우선 | 접근 방향 경계 강화 |
| 전방 고속 소형정 접근 | 전방 집중 감시 | 근접 보호 강화 |
| 양측 동시 접근 | 양측 균등 대응 | 위험 접촉 우선 |
| 후방 추적 선박 접근 | 후방 집중 관측 | 전방 감시 병행 |
| 미식별 드론 접근 | 공중 식별 강화 | 상공 보호 강화 |
| 공중·해상 동시 접근 | 역할 분담 | 함선 중심 보호 |
| 미식별 부유물 유입 | 원거리 식별 | 유입 경로 감시 |
| 통신 교란 의심 | 교란 구역 이격 | 임무 축소·함선 주변 재집결 |
| 수중 접촉 의심 | 추정 구역 확인 | 함선 주변 감시 강화 |

`goal_policy`는 계획 생성의 ETA 계산과 Gazebo 실행의 초기·갱신 목표에 공통 적용된다. track/screen은 접촉 추적·외곽 경계, standoff는 더 먼 이격 관측, protect는 함선 근처 보호, investigate는 추정 구역 확인, avoid는 교란 구역 반대편 이격이다. USV 목표는 함선 안전 여유 구역 밖에 배치하며 기존 추진력 제어로 이동한다. 배정되지 않은 기체는 선택한 호위 대형을 유지한다.

양측 상황의 집중 대응은 접촉별 위험도 입력이 없어 현재 함선과 접촉 사이의 거리로 가까운 대상을 선정한다. 다른 접촉에도 UAV·USV를 남긴다. 공중·해상 역할 분담은 접촉 종류별 배정 수를 다르게 한다. 교란 상황은 통신 불능 기체를 배정에서 제외하고 기존 비상 행동을 유지하며 통신 복구를 자동 판정하지 않는다. 실제 소나·전파 센서와 부유물 수거는 연결돼 있지 않다.

검증: 모든 상황에 두 안·서로 다른 실제 목표, 고장 기체 제외·기체 부족 시 선택 불가, 집중 대상과 반대쪽 관측 유지, 함선 내부 목표·중복 목표 방지 및 기존 승인·취소·대형·1인칭 기능.

## 발표용 랜덤 공격 버튼

상황·대응의 승인대기열 위 `랜덤 공격 발생` 버튼은 `POST /api/mission/random-attack`으로 기존 9개 방어 시나리오 중 하나를 즉시 생성한다. 대응안 2개와 Gazebo 외부 접촉은 기존 생성 경로를 사용한다. 진행 중인 동일 상황은 중복 생성하지 않으며 대기열 4건 한도, 최신 함선 연결, 교란 기체 수 제한을 유지한다. 수동 생성과 자동 생성은 같은 생성 잠금을 사용한다. 버튼 생성 후 다음 자동 생성은 120초 뒤로 미뤄져 발표 중 바로 연달아 생기지 않는다. 자동 생성 자체는 유지한다.
