# MiniCPM-V 4.5 추론 확인

확인일: 2026-10-09 한국시간. 모델 `minicpm-v4.5:latest`, Q4_K_M, Ollama 0.40.1.

설정: think=false, temperature=0, num_ctx=4096, num_predict=256. Gazebo와 동시 실행하지 않았다.

첫 텍스트 요청의 모델 로딩은 약 30.29초, 입력 처리는 약 22.79초였다. 최초 준비 비용을 포함한 기록이며 원인을 개별 분리해서 검증하지 않았다.
같은 텍스트 반복은 입력 토큰 64개 중 63개가 캐시되어 일반적인 새 질문 지연을 대표하지 않는다.
새 이미지 1.04초는 작은 도형 이미지 한 장의 결과이며 실제 Gazebo 화면이나 여러 영상의 처리 속도를 보장하지 않는다.

## GPU

- Ollama ps: 100% GPU, context 4096
- 테스트 뒤 전체 GPU 메모리 사용: 6569 MiB / 16303 MiB (약 6.4 GiB)
- 이미지 추론 성공을 확인했으나 Gazebo 동시 실행과 다중 기체 부하는 미검증

## 해석

6개 요청 중 5개는 기대 내용에 부합했고, 배터리 차이 계산 요청 1개는 답변이 불완전했다. 정확한 수치 비교·계산은 백엔드에서 수행하고 모델에는 계산 결과를 제공하는 것이 적절하다.
JSON 테스트는 action과 vehicle_id를 프롬프트에 명시하고 스키마를 강제한 단순 사례다. 자유로운 명령의 안정적인 해석 능력을 검증한 것은 아니다.
현재 모델은 MVP 시험 후보로 유지할 만하지만, 실행 명령을 무검증으로 전달할 근거는 없다.

## 재현

`python3 scripts/test_vlm.py` (Pillow 필요). Ollama 서버가 실행되어 있어야 한다.
재실행은 로컬 결과 파일을 덮어쓴다. 이미 로드된 모델과 캐시 상태에 따라 시간은 달라진다.
이미지와 원본 응답·API 시간 지표: `outputs/vlm_test/` (Git 제외).
